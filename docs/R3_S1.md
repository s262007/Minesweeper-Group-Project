# R3-S1: golden model, co-simulation and PlayConsole

24 October 2026. R3 was unavailable before the MVP, so R2 (Wassim) did this story with Claude Code. R3 keeps ownership of these files and should review them against the contract; that review is what makes the model an independent reference (see "Independence").

## What is included

| File | Content |
| --- | --- |
| `src/main/scala/minesweeper/model/GoldenModel.scala` | `MinesweeperImpl` trait, `Snapshot` (the public CoreIO view in plain Scala), `GoldenModel` |
| `src/main/scala/minesweeper/model/ModelSolver.scala` | v1 solver (CONTRACT 5.6, rule 1 to a fixpoint) for the co-simulation of hints |
| `src/test/scala/minesweeper/GoldenModelTest.scala`, `ModelSolverTest.scala` | Model tests, no Chisel |
| `src/test/scala/minesweeper/ChiselImpl.scala` | Drives a simulated `MinesweeperCore` through the command handshake |
| `src/test/scala/minesweeper/CoSimTest.scala` | Model and hardware in lockstep, compared after every command |
| `src/test/scala/minesweeper/PlayConsole.scala` | Terminal game on the simulated Core, checked live by the model |

The model follows CONTRACT 3, 4 and 5.2: NewGame validation order, first-click protection, the LFSR placement of 4.1, frontier cascade with its layer count, flags, win and loss, revision and the four operation counters. Geometry comes from R3's `RefGrid`. Only data is read from `MsParams` (capacity, presets, limits, defaults), never its index or neighbour helpers.

## What the co-simulation compares

After every command: the result (status, changed, revision), config, state, every public cell over the full capacity (padding included), hints and hintsValid, minesLeft, exploded, revision, generationCycles, revealCycles and revealLayers. solverCycles is implementation-defined (v2 lanes change it), so only "the solver ran" (nonzero) is compared. The snapshot is sampled while the Core holds its result, before result.fire.

On a mismatch the test prints the differences, the last 40 commands, the model's mine layout and both boards.

Fast tests (run on every PR):
- invalid NewGame settings (preset, mine count, seed) and coordinates in padding;
- flags before the first click, wrong flags, reveals of flagged cells, flags on revealed cells;
- a won game, a lost game with a flag on a mine, and the no-op moves after them;
- a large preset followed by a smaller one (stale padding), on two capacities;
- one random sequence of 40 commands on each verification capacity: 4x4, 7x5 with three presets, 5x6 with two presets.

Slow tests (`minesweeper.Slow`): longer random sequences (4 seeds x 80 commands per capacity) and the 30x24 production capacity on settings, flags and range errors of all five presets. A played game at 30x24 needs hours with the default simulator, so production-size games are left to a faster simulator or to hardware-in-loop on the FPGA.

Mutation checks (not committed): a model cascade that expands from numbered cells failed the flags test after 6 commands; a Core that skips `revealAllMines` on a loss failed the win/loss test (minesLeft 11 instead of 12: the flag on the mine was not cleared). Both were reverted.

## Play

```text
sbt "set Test / run / fork := true" "set Test / run / connectInput := true" "Test/runMain minesweeper.PlayConsole 6 6 5 1"
```

Arguments: columns, rows, mines, seed. Commands: `r <row> <col>`, `f <row> <col>`, `a` (reveal a safe hint), `h` (hints on/off), `n [seed]`, `q`. Add `--model` to play on the model alone, or `--script "r 2 2; a; q"` to replay commands. Each move prints the board computed by the hardware, its clock cycles and whether the golden model agrees. On 6x6 the first click takes about 8 s of simulation (28 clock cycles) and a flag about 2 s.

## Contract readings to confirm

1. A Reveal or Flag in a terminal state is a successful no-op even with coordinates outside the grid (terminal check before Range). The contract does not order the two.
2. A flag after the first reveal reruns the solver, so hints stay valid; before the first reveal the game stays Idle without hints.
3. After the winning reveal the solver runs, so a won game shows valid hints (the deducible mines).
4. generationCycles is the number of LFSR candidates, as documented for MineGen.

The Core matches all four. If the team reads one differently, change the model and the Core together.

## Independence

The same AI assistant wrote R2's RevealEngine and Solver. The model was written from the contract text with coordinate loops and shares no code with them, and the mutation checks show the comparison can fail. A review by R3 remains the real independence check.

## Not included (R3-S2 and later)

UartRx/UartTx, the host client connected to a real port, a TestLoad adapter, ScalaCheck properties and the exact oracle.
